# Architecture Decision Records

## 철학
칠판에서 실제로 아이들이 즐기는 것이 최우선. 오래된 기기에서 확실히 돌아가는 단순한 기술을 고르고, 서버 없이 정적으로 유지한다. 지금 필요한 것만 만들되 게임을 추가할 자리는 남겨둔다.

---

### ADR-001: 안드로이드 앱 대신 웹앱
**결정**: 정적 웹앱(SPA)으로 만들고 칠판 내장 브라우저로 접속한다.
**이유**: 칠판에 Play Store가 없어 APK를 수동 설치해야 하고, 출처를 알 수 없는 앱 설치가 막혀 있을 수 있다. 웹은 URL만 열면 되고, 업데이트가 즉시 반영되며, 집의 다른 기기에서도 그대로 된다.
**트레이드오프**: 칠판 브라우저 버전에 묶인다(→ ADR-006에서 실측한 Chrome 99에 맞춘다). 오프라인 플레이는 MVP에서 지원하지 않는다.

### ADR-002: Vite + React + TypeScript + SVG
**결정**: Vite로 빌드하는 React+TS 앱. 퍼즐·조각은 SVG로 그린다. 처음에는 `@vitejs/plugin-legacy`로 구형 Chrome용 번들도 함께 만들었으나, 칠판 실측 뒤 ADR-006에서 뺐다.
**이유**: 게임이 늘어날수록 메뉴·설정·점수판 같은 UI를 컴포넌트로 재사용하는 이점이 크다. SVG는 해상도와 무관하게 선명하고(4K) 요소별 터치 처리가 쉽다. 게임 수준의 그래픽이 필요 없으므로 Phaser 같은 엔진은 과하다.
**트레이드오프**: Vanilla+Canvas보다 번들이 크고 약한 SoC에서 다소 무겁다 → 드래그 중 React 렌더를 피하는 것으로 보완. 쓸 수 있는 CSS·JS 범위는 ADR-006의 대상 브라우저(Chrome 99)로 정한다.

### ADR-003: GitHub Pages 배포
**결정**: 공개 GitHub 저장소 + GitHub Actions로 GitHub Pages에 배포 (`paurrr.github.io/boardgame`).
**이유**: 무료이고 코드 보관과 배포가 한 곳에서 된다. 서버가 필요 없다.
**트레이드오프**: 무료 플랜은 저장소가 공개여야 한다 → 원작 상표·이미지를 쓰지 않는다(ADR-004).

### ADR-004: 원작 카드 대신 퍼즐 자동 생성
**결정**: 조각을 실제로 이어 붙여 만든 모양을 목표로 내는 생성기를 쓴다. 공개 명칭은 "블록 퍼즐".
**이유**: 원작 카드 복제를 피하면서 무한한 문제를 얻는다. 배치로 만든 모양이므로 항상 풀린다. 쉬움은 회전만으로 생성해 뒤집기 없이 풀린다.
**트레이드오프**: 같은 난이도 안에서도 체감 난이도 편차가 있다 → 바운딩박스 채움률로 반듯한 모양을 골라 줄이고, 필요 시 솔버 탐색량으로 보정한다.

### ADR-005: 난이도별 놓기 방식 + 실루엣만 표시
**결정**:
- 퍼즐판에는 목표 모양의 실루엣만 그리고, 정답 배치를 드러내는 조각 경계선은 그리지 않는다.
- 쉬움(`inside`): 조각의 모든 칸이 목표 모양 안이고 겹치지 않을 때만 놓인다.
- 보통·어려움(`free`): 판 격자(목표 바운딩박스 + 사방 2칸 여유) 안이면 목표 밖으로 삐져나와도 놓이고, 겹침만 막는다.
- 정답은 두 방식 모두 "목표 칸 전부 덮음 + 목표 밖 조각 칸 없음"이다.
**이유**: 어린아이(쉬움)는 엉뚱한 자리에 놓여 헷갈리는 일이 없어야 하고, 큰 아이(보통·어려움)는 실물처럼 걸쳐 놓고 맞춰보는 재미가 있어야 한다.
**트레이드오프**: 쉬움은 실물보다 약간 힌트가 된다(삐져나가는 배치를 시도할 수 없음). 보통·어려움은 여유 칸 때문에 판이 커져 같은 칸 너비에서 칸 크기가 작아진다.

### ADR-006: 칠판 실측에 맞춘 빌드 대상 (Chrome 99), legacy 번들 제거
**실측** (2026-10-14, 칠판에서 `check.html`):
- 기기 LG 55TR3DK, Android 11, 내장 Chrome 99.0.4844 (WebView 아님)
- 화면·뷰포트 1280×720 CSS px, `devicePixelRatio` 3 (실제 4K)
- PointerEvent·전체화면 API·localStorage·WebAudio·ES 모듈·CSS 변수 모두 있음
- `navigator.maxTouchPoints`는 1로 나오지만 실제 동시 터치는 17점까지 된다. 게임 안에서 4명이 동시에 끌어도 된다

**결정**:
- `@vitejs/plugin-legacy`(와 그 의존성 `terser`)를 빼고 `build.target`·`cssTarget`을 `chrome99`로 정한다. Vite 7 기본 대상(chrome107)이 칠판보다 새것이라 직접 정해야 한다.
- 쓸 수 있는 CSS·JS를 Chrome 99 기준으로 넓힌다(CLAUDE.md). `tsconfig`의 lib을 ES2022로 두어 그 뒤 API를 타입 단계에서 막는다.
- 최대 인원 4명은 그대로 둔다(동시 터치 17점).

**이유**: Chrome 99는 모던 번들을 받으므로 legacy 번들은 칠판에서 쓰이지 않았다(Chrome 64 미만만 legacy를 받는다). 빼면 빌드가 단순해지고, 구형 가정 때문에 막아 둔 CSS(flexbox `gap` 등)를 쓸 수 있다.

**트레이드오프**: Chrome 99보다 오래된 기기에서는 흰 화면이 나온다. 그때는 아래 순서로 되살린다.
1. 그 기기에서 `/boardgame/check.html`을 열어 Chrome 버전을 확인한다(빌드를 거치지 않는 ES5라 어디서든 열린다).
2. `npm i -D -E @vitejs/plugin-legacy@7.2.1 terser@5.51.2`
3. `vite.config.ts`에 `legacy({ targets: ['chrome >= <버전>'] })`를 넣고 `build.target`은 지운다(plugin-legacy가 모던 번들 대상으로 덮어쓴다). `cssTarget`은 `chrome<버전>`으로 낮춘다. 지우기 직전 설정은 `git show 0cb6498:vite.config.ts`로 볼 수 있다.
4. plugin-legacy는 CSS를 폴리필하지 않는다. 그 버전에서 안 되는 CSS를 margin 등으로 바꾼다. 예: flexbox `gap` 84+, `inset` 87+, `aspect-ratio`·`:is()/:where()` 88+.
5. `tsconfig`의 lib과 CLAUDE.md의 CSS·JS 규칙을 그 버전에 맞춘다.
6. `npm run build` 뒤 `dist/assets`에 `index-legacy-*.js`·`polyfills-legacy-*.js`가 생겼는지 확인한다.

### ADR-007: 빠르기 보너스, 판 전체 타임어택, 총 걸린 시간으로 동점 처리
**결정**:
- 점수는 순위 점수 + 빠르기 보너스다.
  - 순위 점수는 그대로다: 1등 3점, 2등 2점, 그 뒤로 푼 사람 1점, 못 풀면 0점.
  - 빠르기 보너스: 기준 시간의 1/3 이내에 풀면 +2, 2/3 이내면 +1, 그 뒤는 +0이다(경계 포함).
  - 기준 시간은 "라운드마다" 방식이면 라운드 제한시간, "판 전체" 방식이면 판 전체 시간 ÷ 라운드 수다.
- 시간 방식은 설정에서 두 가지 중 고른다.
  - 라운드마다(기존): 라운드마다 60/90/120초 제한.
  - 판 전체(새 타임어택): 모든 라운드를 합쳐 T초. T는 설정 화면에서 −10초/+10초 버튼으로 정한다(30~600초, 기본 300초). 모두가 시계 하나를 같이 쓴다. 라운드 결과 화면과 카운트다운 동안에는 시계가 멈춘다. 판 시간이 다 되면 그 라운드가 끝나고, 라운드 결과를 보여준 뒤 남은 라운드 없이 최종 결과로 간다.
- 총 걸린 시간: 플레이어별로 푼 라운드는 푼 시간, 못 푼 라운드는 그 라운드가 끝날 때까지의 길이를 더한다. 최종 결과에 "총 1분 02.3초 · 4/5 완성"처럼 보여준다.
- 동점 처리: 총점이 같으면 총 걸린 시간(0.1초 단위)이 짧은 쪽이 앞선다. 시간까지 같으면 공동 우승이다.

**이유**: 같은 순위라도 빨리 푼 노력을 보상하고, 혼자 할 때도 점수 차이가 생긴다. 구간 보너스는 아이가 이해하기 쉽다.

**트레이드오프**: 판 전체 방식에서는 가장 늦게 푸는 사람이 모두의 시간을 쓴다. 사람마다 시계를 두는 방식은 아이가 혼자 탈락할 수 있어 택하지 않았다. 판 전체 방식의 보너스 기준(전체 ÷ 라운드 수)은 판 시간을 짧게 잡으면 보너스를 받기 어렵다.

### ADR-008: 쌓기 퍼즐(2탄) — SVG 정사영 3D, 자유로운 판 돌리기, 가까운 자리로 붙기
**결정**:
- 3D 표현은 WebGL 없이 SVG 정사영으로 한다. 정육면체 꼭짓점을 시점(방향각 az, 기울기 el)으로 투영해 보이는 면만 다각형으로 그린다. 판은 손가락으로 잡고 좌우로 360° 돌리고(1px당 0.6°) 위아래로 기울인다(15~85°, 1px당 0.35°).
- 판에 바깥 여유 칸을 두지 않는다(1탄 ADR-005의 사방 2칸과 다르다). 빗나간 놓기는 가까운 자리로 붙여 받아 준다(`SNAP_RADIUS` 0.9 판 단위). 놓기 전에 붙을 자리를 진하게 미리 보여 주고, 못 놓는 끌기는 흐리게(0.5) 보인다.
- 쉬움의 목표는 일부 칸만 2층인 "높이가 섞인 건물"이다. 원안인 "평면 조각 2개로 바닥 전체를 2층까지"는 전수 조사에서 서로 다른 평면 2개로 풀리는 퍼즐이 0개여서 바꿨다.
- 트레이의 조각과 판 밖에 둔 조각은 판의 0.6배로 그린다. 집으면 1배가 된다.
- 판 돌리기와 조각 회전 애니메이션(220ms)은 매 프레임 꼭짓점을 다시 투영해 그린다. 끄는 중 조각 위치는 여전히 `transform`을 직접 갱신하고, 떨어질 자리 표시는 자리가 바뀔 때만 React 상태를 바꾼다.
- 제한시간 선택지를 게임별로 둔다. 쌓기 퍼즐은 90/120/150초(기본 120초), 블록 퍼즐은 그대로 60/90/120초. 1인 최고기록도 게임별로 따로 저장한다(블록 퍼즐은 기존 키, 쌓기 퍼즐은 `boardgame.stack.best.v1`).
- 칠판 성능 확인 동안 쌓기 퍼즐은 메뉴에서 숨기고 주소에 `?dev`를 붙였을 때만 열었다. 2026-10-25 칠판에서 판 돌리기·회전·끌기가 잘 된다고 확인해 숨김을 풀었다. 숨긴 게임 장치(`hidden`, `?dev`)는 다음 게임을 위해 남긴다.

**이유**: 판을 돌려 2층에 가려진 1층을 보는 것이 이 게임의 핵심이다. 실험 결과 정사영 SVG로 충분했고, WebGL은 칠판 Chrome 99에서 부담과 위험이 크다. 여유 칸을 빼야 4인 칸에서 판을 키울 수 있고, 붙기와 미리보기가 빗나감을 메운다. 아이에게 풀리는 퍼즐이 있어야 해서 쉬움의 목표를 바꿨다. 2층 퍼즐은 시간이 더 걸려 제한시간을 늘렸고, 두 게임의 기록이 섞이거나 덮어쓰이면 쓸모가 없다.

**트레이드오프**: 매 프레임 다시 그리므로 1탄의 "끄는 중 transform만" 규칙과 UI 가이드의 "transform·opacity만 애니메이트"의 예외가 된다(CLAUDE.md에 한 줄). 칠판에서 끊기면 돌리는 동안 빈칸 표시·테두리 생략 → `points` 직접 갱신 → 45° 단위 맞춤 순으로 줄이고, 그래도 안 되면 방식을 사용자와 다시 정한다. 트레이 0.6배는 "조각과 판은 같은 칸 크기" 원칙과 다르다(의도적). 보통 난이도의 서로 다른 퍼즐은 약 110종이라 반복된다.

### ADR-009: 과일 종치기(3탄) — 원작 규칙, 칸마다 종, 톡 판정, own 게임
**결정** (규칙 세부: `docs/superpowers/specs/2026-10-25-fruit-bell-design.md` §4·§5.1):
- 원작 규칙 그대로다. 맞게 친 사람이 다음 카드를 뒤집고, 엎은 더미가 비면 즉시 탈락하며, 마지막 한 명이 남을 때까지 한다. 핸디캡은 없다.
- 종은 칸마다 하나이고 톡(`isTap`)만 인정한다. 순서는 닿은 시각(`pointerdown`의 `timeStamp`)이고, 더 이른 누름이 남아 있으면 톡인지 정해질 때까지 기다리고, 그동안 뒤집기를 막는다. 첫 톡 하나만 판정하고 늦게 친 사람은 벌칙이 없다.
- 셸 확장: `GameModule`을 `PuzzleGame | OwnMatchGame` 합집합으로 바꾼다. own 게임(`kind: 'own'`)은 `Match`로 경기 화면 전체를 맡고, 설정에서는 인원·이름만 고른다.
- 과일 색은 1탄 조각 색에서 빌린다. 처음에는 `hidden`으로 `?dev`에서만 열었고, 2026-10-25 메뉴에 공개했다.
- 판 전체 난이도(원작에 없는 집 규칙, 2026-10-25 추가): 쉬움 = 원작(시간 제한 없음·카드 전부), 보통·어려움 = 차례 제한시간 3초에서 한 장마다 0.05초씩 줄어 1초·0.5초까지, 사람당 12·8장. 시간이 다 되면 저절로 뒤집는다(종 판정을 기다리는 동안은 미룬다). own 게임은 `levels`(단계별 설명)를 주면 설정에 난이도 줄과 설명이 나온다.

**이유**: 모두가 같은 것을 보고 17점 멀티터치로 동시에 손을 뻗는 게임이다. 종이 가운데 하나면 가운데 선 사람이 유리하다. 손바닥 짚기 오작동과 거의 동시에 친 판정의 억울함을 처음부터 막는다. 카드가 사람 사이를 오가고 차례가 있어 `onSolved` 계약에 안 맞는다.

**트레이드오프**: 톡을 인정하므로 종소리가 손을 뗄 때 난다. 같은 프레임 안의 터치는 구별하지 못해 처리된 순서로 정한다.

### ADR-010: 짝 맞추기(4탄) — 판 하나 차례제, 이름으로 차례 표시
**결정** (세부: `docs/superpowers/specs/2026-10-25-memory-design.md`):
- 원작처럼 판 하나를 두고 차례대로 한다(맞히면 한 번 더). 1~4인.
- 난이도는 장수와 틀린 두 장이 보이는 시간이다(16장·3초, 32장·2초, 48장·1초).
- 차례는 이름을 사람 색 글씨로 쓰고, 판 테두리도 그 색으로, 넘어갈 때 배너를 띄운다.
- 카드는 손을 뗄 때 탭(`onTap`)으로 판정한다.
- own 게임에 `store`를 넘긴다. 1인 기록은 뒤집기 횟수로 `recordBestTime`을 쓴다.
- id `pairs`(`memory`는 `memoryStore`와 헷갈림). 처음에는 `hidden`으로 `?dev`에서만 열었고, 2026-10-25 칠판에서 확인해 메뉴에 공개했다.

# 설계: 3탄 "과일 종치기" (반응 속도 카드 게임)

- 작성일: 2026-10-25
- 상태: 설계 승인, 구현 전
- 범위: 새 게임 모듈 `src/games/bell/`과 공통 셸 변경(§6): 게임이 경기 화면 전체를 맡는 방식, 인원·이름만 고르는 설정 화면

## 1. 왜 만드나

- 칠판에서는 "나만 아는 정보"가 있는 게임(손패 카드 등)이 안 된다. 모두가 같은 걸 보고 겨루는 게임이 맞다.
- 지금 있는 두 게임(블록 퍼즐, 쌓기 퍼즐)은 모두 혼자 푸는 퍼즐이다. 3탄은 결이 다른 **반응 속도 게임**으로, 칠판만의 강점인 17점 멀티터치(여럿이 동시에 손 뻗기)를 살린다.
- 어른과 아이가 칠판 앞에 나란히 서서 한다.

## 2. 결정 사항

**사용자가 정한 것**
- 원작 할리갈리 규칙을 그대로 칠판으로 옮긴다 ("원작대로가 좋음").
- 어른·아이가 **같은 조건**으로 겨룬다. 핸디캡 없음.
- 펼친 카드는 각자 칸 위쪽에 둔다.
- 실패로 치는 것 두 가지(§5)를 처음부터 막는다.

**내가 정한 것** (각 절에 "내 판단"으로 표시)
- 2~4명, 종은 칸마다 하나, 과일 4가지와 색, 나누기·끝내는 방식, 종 판정 방식.

## 3. 하지 않을 것

- 컴퓨터 상대, 1인 모드, 사람마다 다른 핸디캡, 원작 확장판 규칙, 기록 저장. (판 전체 난이도는 §4.1에서 더했다)
- "할리갈리" 이름·원작 그림 사용 (상표). 이름은 **과일 종치기**, 과일 그림은 새로 그린다.

## 4. 규칙 (원작대로)

- 카드 56장: 과일 4가지 × (1개짜리 5장, 2개 3장, 3개 3장, 4개 2장, 5개 1장).
- 섞어서 똑같이 나눠 각자 엎어 둔 더미로 시작. 안 나눠떨어지면 앞사람부터 한 장씩 더 (3명이면 19·19·18장) — 내 판단.
- 차례대로(왼쪽 칸 → 오른쪽 칸 → 다시 처음, 탈락자 건너뜀) 자기 더미를 눌러 맨 위 한 장을 자기 펼친 더미 위에 뒤집는다. 차례 아닌 사람이 누르면 무시.
- 보이는 건 각자 펼친 더미의 맨 위 카드뿐. 어떤 과일이든 보이는 카드의 합이 **정확히 5**면 종을 친다.
- 맞게 치면: 모두의 펼친 더미(탈락한 사람 것도)를 전부 가져가 자기 엎은 더미 밑에 넣고, **맞게 친 사람이 다음 카드를 뒤집는다** (원작).
- 틀리게 치면: 탈락하지 않은 다른 사람마다 한 장씩 준다 (모자라면 있는 만큼).
- 탈락: 엎은 더미가 비면(마지막 카드를 뒤집었거나 벌칙으로 다 줬을 때) **그 자리에서 탈락**한다. 탈락한 사람의 펼친 카드는 다음에 맞게 친 사람이 가져갈 때까지 그대로 보이고 합에 들어간다 (원작).
- 마지막 한 명이 남으면 끝. 순위는 늦게 탈락한 순서. 원작은 "두 명 남으면 다음 종까지 하고 카드 많은 쪽이 이김"과 "한 사람이 카드를 다 가질 때까지" 두 방식을 두는데, 2명으로 시작해도 같은 규칙이 되도록 뒤쪽을 쓴다 — 내 판단.
- 원작 규칙 확인: 2026-10-25, rulespal.com의 할리갈리 규칙서. 즉시 탈락이므로 "모두 뒤집을 카드가 없어 멈추는" 상황은 생기지 않는다.

### 4.1 판 전체 난이도 (2026-10-25 추가, 집 규칙)

PC에서 해 본 뒤 사용자가 더했다. 원작에는 시간 제한도 장수 조절도 없다. 모두 같은 조건이고(핸디캡 아님), 설정에서 쉬움/보통/어려움 한 줄로 고른다.

| 난이도 | 차례 제한시간 | 사람당 카드 |
|---|---|---|
| 쉬움 | 없음 (원작) | 전부 |
| 보통 | 3초에서 한 장 뒤집힐 때마다 0.05초씩 줄어 1초까지 | 12장 |
| 어려움 | 같은 속도로 0.5초까지 | 8장 |

- 시간이 다 되면 차례인 사람 카드가 저절로 뒤집힌다(벌칙 없음). 이것이 자동 뒤집기를 겸한다. 종 제한시간은 따로 두지 않는다 — 다음 카드가 넘어가면 5가 사라진다.
- 종에 손가락이 닿아 판정을 기다리는 동안에는 저절로 뒤집지 않는다. 결과 표시 1.5초 동안은 멈추고, 이어서 할 때 그 차례 시간을 처음부터 잰다.
- 카드를 덜 나눌 때는 섞은 56장의 앞에서부터 "사람 수 × 장수"만 쓴다.
- 사용자 요청: 각 단계의 뜻을 화면에 보인다. 설정의 난이도 줄 아래에 설명이 나오고(숫자는 `BELL_LEVELS`에서 만든다), 경기 중 위쪽 막대에 `보통 · 2.4초`가 나온다. 차례인 칸의 뒤집기 버튼 안 막대가 남은 시간만큼 줄어든다.
- 기본은 보통이고, 마지막에 고른 난이도를 기억한다.

## 5. 화면

```
+----------+----------+----------+----------+
| [펼친카드] |  ...     |          |          |  위 1/3: 이름·펼친 카드 (보기만)
|          |          |          |          |
| [더미 14장]|          |          |          |  아래 2/3: 더미(뒤집기)·종
|  ( 종 )   |          |          |          |
+==========+----------+----------+----------+
```

- 기존 `PlayLayout`(`src/shell/ui/PlayLayout.tsx`)의 칸을 그대로 쓴다. 칸마다 펼친 카드 위, 엎은 더미(남은 장수 표시)와 종이 아래.
- **종은 칸마다 하나**. 가운데 하나면 가운데 선 사람만 유리하다 — 내 판단.
- 차례인 칸은 더미 버튼이 `--accent`로 켜지고, 나머지 칸 더미는 `--off`. 칸 표시 방법은 빌더 몫(그림자·글로우 금지, 테두리로).
- 종을 치면 결과를 칸에 잠깐(약 1.5초) 보여 주고(누가 먼저 쳤는지, 맞음/틀림, 몇 장 오갔는지) 그동안 입력을 막는다.
- 과일은 4가지, 색은 기존 팔레트에서 서로 잘 구분되는 빨강·노랑·초록·파랑을 쓴다(예: 딸기 `#D9442E`, 바나나 `#F2B53A`, 라임 `#8DBB2E`, 블루베리 `#22507C`). 원작(딸기·바나나·라임·자두)과 다르게 하고 보라색도 피한다 — 내 판단. 새 색 하드코딩 금지 원칙에 따라 기존 값만 쓰고 `docs/UI_GUIDE.md`에 과일 색 표를 추가한다.
- 카드는 SVG. 과일 1~5개를 주사위 눈처럼 배치. 1~3m에서 몇 개인지 바로 셀 수 있게 크게.
- 애니메이션: 지금 가이드는 정해진 것 외에 금지 → 카드 뒤집기·카드 가져가기 정도만 `transform`/`opacity`로 허용하도록 `docs/UI_GUIDE.md`에 3탄 절을 추가 (쌓기 퍼즐 절처럼).
- 소리: `src/lib/sound.ts`에 합성음 "땡"(맞음)·틀림 소리 추가.
- 위쪽 막대: 소리·전체화면·그만하기(두 번 누르기)는 그대로. 라운드·시계는 이 게임에 없다.

### 5.1 실패 막기 (사용자 확인)

1. **손바닥 오작동** — 손바닥을 칠판에 짚었는데 종이 울려 억울하게 카드를 뺏기는 것.
   종은 누른 순간이 아니라 **짧게 톡 치고 뗀 것만** 인정한다. 기존 `src/lib/gesture.ts`의 `isTap`(300ms 이내, 10px 이내)을 쓴다. 손바닥을 짚고 있으면 300ms를 넘어 무시된다. 소리는 인정되는 순간 낸다.
2. **동시 판정** — 거의 동시에 쳤는데 판정이 억울하게 느껴지는 것.
   순서는 손가락이 **닿은 시각**(pointerdown의 `timeStamp`)으로 정한다. 더 일찍 닿았는데 아직 떼지 않은 손가락이 있으면 그 결과(톡인지, 오래 누른 건지)를 기다린 뒤 판정한다. 판정 결과는 "○○ 먼저!"로 누가 이겼는지 분명히 보여 준다.

세부 (내 판단):
- 종에 손가락이 닿아 톡인지 기다리는 동안(최대 300ms)에는 뒤집기를 막는다. 5인지는 이긴 손가락이 **닿은 순간**의 카드로 판정한다.
- 여러 명이 쳤으면 가장 먼저 닿은 톡 하나만 판정한다(맞든 틀리든). 늦게 친 사람에게는 벌칙이 없다. 실물에서 늦은 손이 앞 손 위에 얹히는 것과 같다.
- 닿은 시각까지 같아 구별이 안 되면 처리된 순서로 정하고, "○○ 먼저!"를 그대로 보여 준다. 같은 화면 프레임 안에 들어온 터치는 원래 구별할 수 없으니 받아들인다.
- 칠판에서 실제 느낌(톡 인정 시간, 손바닥, 동시 터치 순서)은 칠판 확인 항목으로 둔다.

## 6. 코드 구조

- 새 게임 `src/games/bell/` (`logic/`·`ui/`·`index.ts`), `src/games/registry.ts`에 등록. 칠판 확인 전까지 `hidden: true`(쌓기 퍼즐과 같은 절차).
- **지금 셸 구조와 안 맞는다**: `GameModule`(`src/games/types.ts`)과 `Match`(`src/shell/ui/Match.tsx`)는 "각자 퍼즐을 풀고 `onSolved`로 알린다"는 구조라, 카드가 사람 사이를 오가고 차례가 있는 이 게임은 들어가지 않는다. → 게임이 경기 화면 전체를 직접 맡는 방식을 `GameModule`에 추가하고 `App.tsx`가 그쪽으로 보낸다. 구체적인 모양은 빌더 몫. 단, 블록·쌓기 퍼즐의 동작과 기존 테스트는 그대로 둔다.
- 설정 화면(`src/shell/ui/PlayerSetup.tsx`)은 인원·이름만 보이게 한다(난이도·라운드·시간 숨김). 저장된 설정(`SavedSetup`)의 라운드·시간 값은 다른 게임을 위해 그대로 둔다.
- 다시 쓸 것: `PlayLayout`, `TopBar`(라운드·시계를 빼는 방법은 빌더 몫), `PLAYER_COLORS`, `createRng().shuffle`(`src/lib/random.ts`), `randomSeed`, `isTap`, `sounds`/`unlockAudio`.
- 규칙 로직(덱, 나누기, 차례, 뒤집기, 5 판정, 가져가기, 벌칙, 탈락, 승리, 종 누르기 순서 판정)은 React 없는 순수 TS + Vitest, 테스트 먼저(TDD).
- 최종 결과 화면: 기존 `FinalResult`는 점수·시간 기준이라 그대로는 안 맞는다. 늦게 탈락한 순서로 보여 주고 "다시 하기"·"메뉴"를 둔다. 기존 것을 넓힐지 새로 만들지는 빌더 몫.
